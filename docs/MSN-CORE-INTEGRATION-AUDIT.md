## Material findings for parent handoff

These are source-confirmed defects/gaps, not failed test assertions; no fixes were made.

1. **P1 — concurrent builds can bypass the single-job gate.** `scripts/local-msn-studio.mjs:46` checks `active/admitting` before awaiting the request body and project read, but sets `admitting=true` only afterward. Two requests can both pass the check and start; `start()` overwrites the sole active controller, breaking cancellation and allowing further admission when one finishes. Reserve admission before the first await and release it safely on validation failure. Existing tests exercise the engine, not concurrent HTTP admission.
2. **P1 — one persistence failure poisons all subsequent job saves.** `scripts/local-msn-studio.mjs:17–19` chains writes with `saveChain.then(...)` without recovery. Once a write/rename rejects, future calls never write. Progress/completion calls also ignore rejected promises, risking process termination or a UI claiming completion without persisted state. Publication is mutated in memory before its write succeeds (`:44`), so a failed publish/unpublish may still change the live player gate. Recover the queue and commit state only after successful persistence; add failure-injection integration coverage.
3. **P2 — saved-project and renderer contracts diverge.** `features/msn-local/projects.mjs` rejects renderer-supported `audio.start/end`, `music.timelineStart`, layer `fontFamily`/`fit`, scene `video`, and `logo` layers. It also accepts durations/coordinates/layer counts that the renderer rejects. The real build route reloads the saved project, so direct renderer tests do not establish UI-to-save-to-render support. Align/validate a shared contract without dropping existing fields; preserve optional capabilities through templates and reload.
4. **P2 — voice metadata can assert an unverified speaker.** `article.mjs:11` always labels any uploaded narration as Sam; `studio.html:36` defaults an empty voice to Sam and the renderer copies the selected label whenever audio exists. Neither path establishes the uploaded file's speaker. Retain user-entered labels as unverified metadata; do not present them as provider-confirmed voice provenance.
5. **P2 — upload freshness is not persisted.** `studio-assets.mjs:12` returns `updatedAt` on upload but writes only media bytes; `listStudioAssets()` reconstructs entries without that timestamp. Reload loses successful-update evidence. Persist upload metadata and retain it on reads; file listing/render time must not substitute for update or verification time.

Existing-core gates also need attention before activation: `/api/cron/language-feed` and `/api/cron/rss-builder-crawl` allow requests when the cron secret is absent, and `middleware.ts` exempts `/api/cron` from session authentication. This is a conditional fail-open path, not a claim about current hosted configuration. The language runner marks jobs running without a durable atomic claim or stale-running recovery; interrupted jobs fail `isCronDue()` indefinitely, and overlapping callers can race. Do not infer safe scheduler operation from endpoint presence.

## Missing wiring and gates

**Local integration work, when separately assigned:** adapt the new engine into existing authenticated Studio project/job/Library interfaces; carry source IDs/provenance and Brand Kit selection through saved projects and render snapshots; retain original assets and templates; align the save/render schema; connect existing article imports to editable projects; add deterministic HTTP/job failure tests and existing-template regression checks. The legacy article renderer is specifically Football365/Liverpool/Mac Allister-oriented, not a general importer or reusable multi-brand template.

**Remote work requires explicit authorization:** source/feed fetching, cron execution (including follow-up AI and email), provider synthesis/translation/generation, account configuration, remote database/storage and hosting/MSN publication. A local publish action only enables a loopback player. It does not establish public URLs, remote access controls, ingestion acceptance or distribution. No remote gate was exercised here.

**Freshness acceptance:** retain source publication/observation time separately from successful import/render/upload time and factual verification. Existing language cron success/failure timestamps and watermark are distinct; failed runs must not advance `lastSuccessAt`. Project/Brand Kit tests show ordinary reads and rejected mutations preserve saved timestamps. Render tests retain successful output timestamps. Audit the integration boundary so failed writes/fetches cannot claim fresh content; restore upload metadata and distinguish job-status update time from media update time. No factual verification or production readiness is implied by this audit date.

## Re-review status — 2026-10-28

This appendix supersedes the affected findings above. Only this audit appendix and the explicitly requested `app/lib/language-studio/cron-scheduler.test.ts` were changed in this review; implementation files remained read-only. No server, cron runner, provider, remote service or environment file was invoked/loaded.

- **Finding 1 resolved in source:** `/api/build` now claims `admitting` before its first await and releases it in `finally`. HTTP concurrency was not exercised; the source-level race previously identified is closed.
- **Finding 2 partially resolved:** `persist()` recovers a rejected queue, progress/final writes catch rejections, and publish/unpublish restores the previous value on failure. Remaining: `start()` still exposes `complete` / “Saved to local Library” before the final manifest write succeeds, logging failure without changing the success state. Initial admission also inserts a queued job before persistence; failure leaves that in-memory entry without starting a worker. Publication is visible before its write commits, and overlapping publication requests can interfere with rollback. Queue recovery alone does not establish transactional state or durable completion.
- **Finding 3 substantially addressed:** the project store now derives draft layer/track schemas from the renderer and retains the previously unsupported optional fields; current project/renderer tests pass. Drafts intentionally allow incomplete content and defer timeline-fit checks to build. This is not evidence that every renderer capability has a UI control.
- **Finding 4 partially addressed:** scene output now reports `voice:null`, `requestedVoice` and `voiceProvenance:'unverified'` for supplied narration. The legacy `renderArticle()` still unconditionally returns Sam as its voice label.
- **Finding 5 resolved for successful uploads:** upload names and UTC timestamps are persisted in `uploads/catalogue.json` and recovered by listing; the new existing upload regression test passes. **Residual failure-path gap:** media bytes are written before the catalogue commit. A failed catalogue write/rename leaves an orphan asset that listing still exposes with a null timestamp despite the upload reporting failure. Read errors other than missing-file errors are also treated as an empty catalogue, risking metadata loss on a subsequent write. No failure injection was run against this path.

### Scheduler test results and behavior

Added 27 deterministic tests importing only `cron-scheduler.ts` plus its type definitions. **26 passed; 1 failed.** The failing regression remains an ordinary failing assertion, not skipped or marked expected-failure, because implementation changes are out of scope.

- **P2 confirmed failure:** hourly `minute:30`, after `2026-01-01T10:10:00Z`, returns `2026-01-01T11:30:00.000Z`; the next eligible slot is `10:30`. `nextHourlyRun()` unconditionally advances the UTC hour before considering whether the current hour's scheduled minute is still ahead.
- Passing coverage includes minute interval bounds/elapsed-time behavior, hourly exact-slot and two-hour rollover, daily/weekly London DST wall-clock behavior, selected weekdays, a fractional-offset timezone/year rollover, invalid timezone fallback, exact/future/overdue/invalid due dates, inactive/running exclusions, failed-job retry eligibility and nonmutation of timestamps.
- Current DST policy is characterized, not invented: nonexistent spring times are skipped to the next eligible day/week; autumn's repeated local time can run twice. The latter needs a product decision if “once per local day” is intended. Running jobs remain ineligible regardless of age; scheduler tests do not imply runner crash recovery.
- Supported frequencies are **minutes, hourly, daily, weekly**. Monthly is not implemented; normalization currently maps it to hourly. No monthly feature was added.
- Existing local MSN/Brand Kit suite: **41/41 passed** using `node --test --test-reporter=dot features/msn-local/*.test.mjs features/brand-kits/store.test.mjs`. Scheduler tests ran through installed `vitest/node` with `run:true`, `watch:false`, `cache:false`, and Vite `envDir:false`. The earlier 69-test import/helper run was not repeated and remains prior-run evidence.
